# Task Qualifier

## Purpose

Classify incoming work before execution so the factory chooses the right rigor, tools, evidence level and gates.

## Activate when

Every non-trivial task enters the factory, especially when scope, risk, deliverable or authority is unclear.

## Workflow

1. Identify requested outcome and actual deliverable.
2. Classify task domain: engineering, research, design, data, marketing, operations, legal/policy, mixed.
3. Score consequence/risk: low, medium, high.
4. Determine whether fresh external information, private project data, files or repository access is required.
5. Identify destructive actions, writes, deployments, money/legal consequences or production impact.
6. Select the minimum capability set and required gates.
7. Return a short execution contract before complex work begins.

## Output contract

- objective;
- task class;
- risk level;
- required inputs/evidence;
- activated skills;
- required gates;
- completion criteria;
- blockers.

## Guardrails

- Do not turn qualification into a long planning ceremony for simple tasks.
- High-cost wrong answers automatically route to Research & Truth.
- Repository changes route to Repo Intake before editing unfamiliar code.
